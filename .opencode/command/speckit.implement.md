6. **PDCA Quality Enforcement** (MANDATORY — before executing any task):
   
   Read `.agent/skills/pdca/references/do-prompts.md` and `.agent/skills/pdca/references/testing-anti-patterns.md` for complete rules.
   
   **Before every test task — Called Shot Protocol** (NON-NEGOTIABLE):
   - Announce: **Test name** (descriptive), **Behavior under test** (observable behavior), **Expected failure** (exact assertion/error message)
   - Write the test and run it → verify it FAILS with the EXPECTED failure
   - If actual failure ≠ expected failure → **STOP** — diagnose mismatch before writing any production code
   
   **For every task — TDD Red-Green-Refactor**:
   - **RED**: Write the failing test FIRST (compilation errors don't count — use behavioral failures)
   - **GREEN**: Write the MINIMAL code to make the test pass
   - **REFACTOR**: Clean up while keeping the test green
   
   **Test ordering per feature** (MANDATORY):
   1. Degenerate/zero case (empty state, null input)
   2. 1-2 exception cases (invalid input, errors)
   3. Happy path incrementally
   4. Remaining exception cases
   5. NEVER stop with happy path only
   
   **Prohibited patterns** (will cause task rejection):
   - ❌ Choosing mock behavior over system behavior
   - ❌ Tests written AFTER code (if it never failed, it proves nothing)
   - ❌ Vacuous greens (test passes against trivial stub)
   - ❌ Test-only methods in production code
